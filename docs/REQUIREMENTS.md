## 0. 这个项目是什么

一份参考**旧报纸版式**的网页：有报头、分栏、板块、要闻区，版面默认初始排布，用户可重排。

它和普通新闻阅读器的区别有两点，都很关键：

> **一、版面里的内容是活的。** 图片会动，翻页时文字会散开再重组。
>
> **二、版面是"被编辑过的"，不是信息流。** 版面容量有限（一版约 8~15 条），来源每天给几百条。**由 AI 当主编做取舍**——哪条上头版、哪条只配豆腐块、哪条干脆不上。

和市面上"哈利波特魔法报纸"玩具的区别：**它是引擎，不是演示页**。输入任意信息源，输出版面；聚合、编辑、渲染各司其职，每层可替换。

**定位**：信息聚合平台——自己从多源收集信息，AI 主编在有限版面下做取舍与排布，确定性渲染引擎落成版面。
**双受众**（2026-10-17 拍板后仍成立）：①全球开发者（GitHub，README 英文为主+中文版）；②自有内容阵地（公众号「错觉幻视」/ 头条号/ 小黑盒——版面可导出为封面图/短视频的动机来源）。

## 1. 为什么是这个方向（立项依据，均已实测）

### 1.1 查重结论：坑没被占，但隔壁很挤

GitHub 10 组关键词、去重触及 62 个仓库：

| 赛道 | 现状 | 代表 |
|---|---|---|
| RSS → 报纸版式 | 已有人认真做 | `goosepaper` 342★、`unim.press` 249★、`RSSPub` 131★ |
| 哈利波特"魔法报纸" | **全是玩具级，0~1★ 无例外** | ARKit demo、课程作业、个人 portfolio |
| **"会动的报纸 + 真实信息源"** | **空缺** | 最接近的 `daily-tech-prophet` 仅 1★ 且只吃 Reddit |

### 1.2 "图会动"的三档供给（成本从零到有）

实测：开源 README 自带 GIF/视频 = 36%，静态图 = 71% → 大部分条目必须自己造动；新闻配图抓取覆盖率 83%（修懒加载后）→ 拿到的是静图。

| 档 | 手段 | 成本 | 状态 |
|---|---|---|---|
| A | 源自带 GIF/视频 | 0 | 现成，覆盖 36% |
| B | 静图 → Ken Burns / 程序化动图 | 0 | 立刻可做，永不失败 |
| C | 静图 → 真·图生视频 | 见 1.3 | 本地可跑 |

**用户判断记录在案**：图生视频会越来越便宜，靠时间打磨过去；视频生成必须是**可插拔 provider**，不是核心逻辑。

### 1.3 C 档现状：本地已具备，云端不具备（2026-09-21 实测）

云端 key 有效但订阅过期（plan-v3 400 / v3-chat 401）。本地 `F:\ComfyUI` 已装：DynamiCrafter 1024/512（2.93GB×2，专为静图生视频）、插件管线现成。显卡 RTX 5070 Laptop 8151MiB，产出 ~2 秒/1024×576；报纸栏位显示仅 ~600×330，瑕疵在该尺寸下不可见。**零边际成本、离线、不外传**；代价是速度与 2023 年画质。

⚠️ **尚未验证：DynamiCrafter 实际出片质量与耗时——全项目唯一还靠猜的环节（执行顺序①）。**

### 1.4 本期新增实证：The Toddler Times（2026-10-16）

Zara Zhang（@zarazhangrui，9.2 万粉）发布哈利波特风家庭报纸网页 "The Toddler Times"：数小时 1.3 万阅读 / 317 赞 / 112 收藏；评论区已有国人跟做中文版《建造者晨报》（github.com/libuyi543-lang/follow-builders，只吃 Twitter 关注流、无 AI 取舍、无动效内核）。

**它替我们验证了两件事**：

1. 「旧报纸版面 + 栏位里嵌会动的黑白影像」这个视觉方案**成立、有人爱看、可传播**——v0.1 里这还只是设计假设。
2. 跟做者**只有排版没有内核**——我们的三条差异化全部在场：**AI 主编判断 / 翻页重组动效 / 引擎化（任意源可换）**。

## 2. 参照物拆解：Toddler Times 好在哪（2026-10-16）

### 2.1 它的完成度全在细节工程

页面本身几乎没有动效，全部魔法 = "照片是会动的短视频"（黑白、循环、锁栏位、右上角时间码角标 00:12）。但印刷细节全齐：报头口号条（"INDEPENDENT. FAMILY-OWNED. TODDLER-LED."）、刊号行（"VOL. 01 NO. 01 / PRICE: ONE HUG"）、FIG. 编号+图注、虚拟条线署名（"BY OUR BREAKFAST CORRESPONDENT / REPORTING FROM THE HIGH CHAIR"）、版面双标签（"FOOD & DRINK — THE LEAD STORY"）、混合字重头题、斜体导语、拉引句、首字下沉、small-caps 段首词、底部十字导流条（"ELSEWHERE IN HER WORLD"）。截图存档：`refs/01~05`。

### 2.2 拿走什么（映射到需求编号）

| # | 它的做法 | 落到 movable-type | 成本 | 需求 |
|---|---|---|---|---|
| 1 | 影像统一黑白/双色调 | motion provider 出片后统一灰度后处理——多源图色调杂乱，灰度是免费统一器；允许按条目豁免（图表黑白后失读） | 极低 | R6★ |
| 2 | 时间码角标 | media 增加 `timecode` 装饰属性，渲染层画角标 | 低 | R3★ |

| 4 | 口号条 + 刊号行元数据 | masthead 字段化：口号一行；"价格行"位放"本期条数 · 阅读时长" | 低 | R1★ |
| 5 | 五种印刷排版块 | **schema 阶段一次定死**：混合字重头题 / 斜体导语 / 拉引句 / 首字下沉 / small-caps 段首词 | 低（schema 冻结前最后窗口） | R3★ |
| 6 | 虚拟条线署名 | 每 section 配"本报观察员"署名（正经新闻腔版） | 低 | R1★ / EDITOR.md |

### 2.3 观察（不照抄，但记住）

- **魔法克制在媒体层**：页面级动效是配菜，活影像才是主菜——反过来验证翻页 0.8~1.2s、超 1.5s 会烦的判断；**DynamiCrafter 样片（执行顺序①）维持第一优先级**。
- **十字导流条**对视频内容场景 = 天然"下期预告"卡，schema 留 `related_strip` 位（v1.1 实现）。
- **声音**：它有 SOUND ON 开关 → R13（已拍板：预留不实现）。

### 2.4 调性分层红线（新增）

它的戏谑调性建立在内容零风险（自家娃）上；我们讲真新闻：

> **署名层 / 版面标签层可带人设；事实层（标题、正文、图注中的事实陈述）不可玩笑、不可改写。**

§5 的代码红线（`keep_original` 强制 true）不变，本条写入 EDITOR.md 作为其补充。

## 3. 核心需求

### R1 · 版面（旧报纸版式）★含本期扩展

- 报头：刊名、日期、期号、滚动快讯；**顶部口号条；刊号行元数据（本期条数/阅读时长）**
- 分栏：多栏网格，栏间细线，双线分隔
- 板块：栏目名 + 版面角色**双标签**（★）+ **虚拟条线署名**（★）
- 版面元素：主标题（**混合字重**）、**斜体导语**、署名行、正文、图窗（★**时间码角标**）、**FIG. 自动编号 + 图注**、**拉引句**、**首字下沉**、**small-caps 段首词**（★ 后五者为本期新增块型）
- 视觉基调：旧报纸——纸纹、衬线字、墨色、有限彩度；**影像默认灰度化（★，可豁免）**
- 底部十字导流条：schema 留位，v1.1 实现
- **语言策略（★ R14，已拍板）**：内容按原文语言渲染（中英混排是特性）；UI 模板文案中英可切换；产品不内置翻译；见 R14

### R2 · 可重排（不变）

默认初始排布开箱即用；用户可重排栏目顺序/占比/源归属；产物可保存导出（配置文件或 URL 参数）。⚠️ "排布"数据结构是 R3 前提。

### R3 · 版面模型（Paper Model）—— 项目真正内核 ★

- 层级：板块（section）→ 版面（page）→ 区块（block）→ 文本/媒体
- 每块权重/优先级；**图文结构绑定**（图必须跟着自己的新闻走，不许错配）
- **★ v1 冻结的块型清单**：`headline_mix`（混合字重头题）/ `standfirst`（斜体导语）/ `pullquote`（拉引句）/ `dropcap`（首字下沉）/ `smallcaps_lead`（段首小写大写词）/ `figure`（FIG 编号 + caption + timecode + credit）
- **★ 媒体字段扩展**：`{ asset_id, crop_focus, motion, timecode, caption, credit, grayscale_exempt }`
- **★ section 字段扩展**：`tagline`（双标签）、`byline`（虚拟条线署名）
- **★ masthead 字段化**：口号条、刊号行元数据
- **★ 音频占位（R13）**：schema 预留 `audio` 字段与 provider 接口签名，实现空转
- v1 交付物本质：「**一个 schema + 一个渲染器**」

### R4 · 文字动效（不变）

| 场合 | 效果 | 优先级 |
|---|---|---|
| 阅读中 | 保持静止（默认）；可选纸面波浪 | v1 |
| 入场 | 墨迹擦入 + 头条打字机 | v1（已验证） |
| 翻页 | 文字散开 → 重组成新段落 | v1 招牌 |

### R5 · 翻页变形（不变，路线 C 混合快照）

读时真 DOM 文字 → 翻页瞬间引擎自绘 canvas 粒子 → 结束切回 DOM（护城河：只有自己排版的引擎能这么做）。v1 只做**行级飞散**（粒子级 → v1.1 渐进增强），时长 0.8~1.2s。三条实测约束别忘：①逐字定位极快（全页 2170 字 9.8ms）可实时测；②动效层与文本层解耦（打字机把 137 字拆成 138 节点）；③位置采集必须在静止态（动画中 rect 读数不可靠，错位不报错只显怪）。

### R6 · 图会动 ★

- A/B/C 三档供给 + motion provider 插拔 + **fail-safe 退回 Ken Burns**（绝不许版面开天窗）+ 离线预生成缓存（不变）
- **★ 统一后处理**：所有 motion 产出（含 A 档源 GIF）默认过灰度/双色调；`grayscale_exempt` 可按条目豁免（AI 主编决策字段，写入 EDITOR.md）
- **★ 栏位锁定**：动图锁栏位宽高比、循环播放、不做全屏播放器、文末 credit（TT #8）
- 后处理放**离线预处理**（ffmpeg）而非运行时 CSS filter：视频导出链路（R8）要录进同一份素材（C5）

### R7 · 数据源适配（不变）

RSS / 通用 JSON / Markdown；**薄适配层**（只翻译成 Paper Model，不含排版逻辑）；**必须内置示例数据**（clone 下来一条命令看到效果）。

### R8 · 导出 ★（需求保留，v1 优先级后置——2026-10-17 拍板 Q2）

版面 → 封面图 PNG；版面 → 短视频 MP4（喂公众号/头条/小黑盒）。仍是防"看一次就腻"最确定的手段，但 v1 主交付为网页版，导出链路移入 v1.x 第一批。

### R9 · 输出形态（不变）

纯静态 HTML（单文件或静态站），可托管 GitHub Pages；零依赖默认档；重动效渐进增强，不可用自动降级。

### R10 · 信息采集 ★（2026-10-17 拍板 Q3：泛新闻）

- 从多异构来源收集条目：RSS / API / 网页 / 已有聚合器输出
- 必须做：跨源去重聚类、时间归一化、来源分级
- 采集失败退化为缓存，不许版面开天窗
- 参考实现：本地信息台 `newsdesk`（20 源 462 条实测）——**但 newsdesk 偏科技**；泛新闻需要**扩源**（时事/财经/文化等类别，扩源清单在采集层实现时定，见 §8-⑥）
- **内置示例数据用泛新闻混合**（对齐 R7 零配置体验 + Q3 拍板）

### R11 · AI 主编（不变，见 §5）

### R12 · 图片处理（不变）

选哪张（图稿结构绑定）/ 怎么裁（crop_focus 焦点裁切，源图比例各异）/ 动不动（**本身就是编辑判断**，最有效的省算力闸门）。

### R13 · 音频（★ 新增，2026-10-17 拍板 Q5：预留空间，alpha 不做）

- schema 预留 `audio` 字段（环境音/翻页纸声）与 provider 接口签名，**渲染层 v1 不实现、不出 UI**
- alpha 版本零音频；将来实现时默认静音 + 可开（学 TT 的 SOUND ON 但默认关）

### R14 · 语言策略 ★（2026-10-17 拍板 Q4+Q7：内容原文语言，不内置翻译）

- **内容层：原文是什么语言就渲染什么语言**——中文源出中文、英文源出英文，中英混排是特性不是缺陷；需要整页翻译的读者用浏览器自带翻译 / 沉浸式翻译等**网页翻译工具**（出版物是网页，这条路天然存在，且不经过我们的管线）
- **UI 层双语**：报头、栏目名、版面角色、署名头衔、图注前缀、按钮等模板文案带语言维度，中英一键切换
- **产品不内置任何 AI 翻译**——`keep_original` 红线因此完好无损（Q7 张力消解，见 §10）
- 字体策略：中文衬线铅字（候选思源宋体/Noto Serif SC，具体选型实现时定）+ 西文衬线（候选 Playfair Display / EB Garamond）；混排按字符集做字体回退
- CJK 约束（C4）作用于中文文本；英文文本享受拉丁排版默认规则
- 残余排版项（并入风险 9）：中英混排的基线对齐、标点挤压、避头尾

## 5. 信息采集与 AI 主编

### 5.1 分层架构（AI 只碰"决策"，不碰"渲染"）

```
数据源(N 个)
   ↓  采集：抓取 / 去重 / 归一化
条目池（几百条）
   ↓  粗筛：规则打分（复用 newsdesk 六维重要性评分）
候选池（几十条）
   ↓  ★ AI 主编：一次 LLM 调用，输出结构化「编辑决策」
版面决策（JSON）
   ↓  排版引擎：确定性执行
活报纸版面
```

**硬架构约束：AI 绝不直接产出 HTML / CSS / 坐标。** AI 出错时最坏情况只能是"选题选得不好"，绝不能是"版面崩了"。

### 5.2 输入 / 输出契约

**输入**（每条已归一化+粗筛）：`{ id, title, summary, source, source_tier, published_at, score_breakdown: {六维}, assets: { images[], has_video, aspect_ratios[] } }` + 版面容量约束。

**输出**（结构化编辑决策，不是自由文本）：

```jsonc
{
  "issue": { "date": "...", "lead_id": "...", "slogan": "..." },
  "sections": [
    { "name": "头版", "tagline": "今日头条", "byline": "本报科技观察员",
      "blocks": [
        { "item_id": "...",
          "weight": "lead | feature | brief",
          "image": { "use": true, "asset_id": "...",
                     "crop_focus": [0.5, 0.35],
                     "motion": "kenburns | video | none",
                     "grayscale_exempt": false },
          "headline": { "style": "normal | large | mix", "keep_original": true } }
      ] }
  ],
  "dropped": [ { "item_id": "...", "reason": "..." } ],
  "editor_note": "本期判断的一句话说明"
}
```

四要求：**可解释**（dropped 必带 reason）/ **可复现**（低温度+固定模型版本）/ **可离线**（决策缓存落盘）/ **失败可回退**（LLM 挂了按分数兜底，版面照常出）。

### 5.3 红线（内容合规，不可协商）

> **AI 只能"选择和排布"，不能"改写和编造"。**

- ❌ 不许改写标题/摘要成原文没有的事实；不许补充背景/数字/引语；不许生成"看起来像原文但不存在"的句子
- ✅ 允许：截断、选择、排序、分组、定字号、定标签
- **落地方式**：AI 输出不含任何新句子——`keep_original` 默认且只能是 `true`，版面文字一律从原文切片。**代码强制，不靠提醒。**
- **★ 调性分层补充（2026-10-16）**：署名层、版面标签层可带人设；事实层不可玩笑、不可改写。
- **语言策略（Q7 已决）**：内容原文语言渲染、产品不内置翻译；UI 模板文案带语言维度中英切换（§10）

### 5.4 成本控制

两级漏斗：规则粗筛（≈0 成本，几百→几十条）→ AI 精排（一次调用出整版决策，结果缓存）。具体 token 量实现时实测。

### 5.5 图片处理

| 环节 | 决策（AI） | 执行（引擎） |
|---|---|---|
| 选哪张 | 从候选图挑 | 图稿结构绑定，不许错配 |
| 怎么裁 | `crop_focus` 焦点坐标 | 按栏位比例裁切 |
| 动不动 | `motion: kenburns / video / none` | video 走 provider，离线预生成+缓存 |
| 灰不灰 | `grayscale_exempt`（★新增） | 默认灰度后处理，豁免条目原色 |

## 13. 下一版本候选：事件追踪与故事发展脉络

> 2026-10-17 补充，来自用户对下一阶段信息获取方式的讨论。**本节记录产品方向，供下一版本推进时评估加入；不视为当前 v1 的必交付项，不修改既有内容红线。** 新闻档案库是更后续的可选扩展。

具体流程、数据契约、交互、失败回退、开发拆分与验收见配套文档：[事件追踪 · 产品与技术实施规格](EVENT-TRACKING-SPEC.md)。其中实现方案与试验参数为下一版本设计草案，尚不代表已确认排期。

### 13.1 目标与基本原则

在保留广泛新闻接触的同时，让读者主动追踪某件事情，经过一两个月，能够看清它如何发展、有哪些直接进展，以及哪些其他事件间接影响了走向。

**普通新闻保持随机探索，追踪内容形成连续故事线。** 两者并存，不能因用户关注了一件事，就把其他内容逐渐替换成相似新闻。这里的“推送”指产品内的内容分发与展示，不预设系统通知或其他外部通知渠道。

- **随机探索**：大部分普通新闻继续保留随机发现机会，不以点击、停留或“不感兴趣”持续收窄全部新闻范围。随机选择仍应经过基础质量、时效与去重筛选，不等于无条件抽取垃圾内容。
- **重要信息可见**：不能只因用户没有表现出兴趣，就过滤可能重要的公共信息；具体保障机制与探索比例待定。
- **主动追踪**：读者显式选择追踪某件事；阅读或点击一篇文章不自动等于开启长期追踪。
- **长期积累**：故事线跨期保存，不能每次出报重新生成、丢失既有脉络。

### 13.2 R15 · 开启与关闭事件追踪（候选）

- 新闻条目提供“追踪这件事”入口，创建或关联一个稳定的事件故事线；多篇报道可归属同一事件。
- 开启后，记录关注时间；以后相关或间接相关的内容可进入这条故事线，随每期新闻展示新增进展。
- 用户可随时关闭追踪。**关闭即归档**：退出活跃追踪与后续更新展示，保留关闭前已积累的故事线，不等于删除。
- 归档后的内容先保留存档；统一检索、管理与重读入口可在未来“新闻档案库”中实现，不要求本阶段建设完整档案库。

### 13.3 R16 · 故事线增量更新（候选）

- 每天检查活跃事件是否出现新进展；有实质新增信息时，追加节点，而非把同一件事反复当成新新闻。
- **不要求每天强行新增一个环节**：没有实质进展时可显示“暂无新进展”，不得为了保持日更而编造或凑节点。
- 同一进展的多篇转述合并到同一节点，保留多个原文来源；新增事实、后续结果与更正可作为更新记录。
- 区分事件发生时间、报道发布时间、系统收录时间；未知时间明确标注，不能把收录日期冒充发生日期。
- 更正应关联被更正的节点，保留变更记录，避免读者继续沿用旧说法。

### 13.4 R17 · 故事发展脉络视图（候选）

读者可随时打开关注事件的“故事发展脉络”，查看时间线及主线、支线。

| 组成 | 需求 |
|---|---|
| 关注起点 | 明确标出用户开始追踪的时间，作为阅读参照点，不作为事件本身的起点 |
| 向前回溯 | 展示关注之前已发生、与理解当前事件有关的历史节点；按来源可获得的范围补齐，缺口明确标注，不承诺完整历史 |
| 向后发展 | 持续展示关注后实际发生的新进展；“往后”指后续事实，不是预测未来 |
| 主线 | 事件本身的直接发展，如提出、推进、变化、结果及更正 |
| 支线 | 可能间接影响事件走向的其他事件；应能看出它与主线哪个节点相关，以及关联依据 |
| 来源 | 每个节点能展开查看原文片段、来源链接与相关时间信息 |

支线不是所有相似话题的集合。**相关性不等于因果性**：来源没有支持的影响关系不能写成确定事实；关联存疑时标记待确认，并允许人工纠正。一个支线事件可关联多条故事线，避免反复复制成彼此独立的记录。

### 13.5 AI 的职责与现有红线

- AI 可辅助识别同一事件、合并重复报道、提出主支线归属及关联建议；应保留来源依据与可纠正的记录。
- 新闻事实继续取自原文，遵守 §5.3 的选择、排布与原文切片限制。本节**不授权 AI 生成故事正文、补写历史背景或编造因果解释**。
- 早期故事线可由原文标题、原文片段、日期及结构化关系组成；如果以后需要 AI 生成综合叙事，须另行评估引用、校验与内容红线，不作为本节默认能力。

### 13.6 建议验证顺序与验收方向

以下为实施建议，排期未定：

1. **先做连续性**：稳定事件标识、主动追踪、跨期保存、增量节点及关闭归档；同一事件跨多期仍能打开同一条故事线。
2. **再做脉络**：以关注时间为参照向前回溯、向后展开，增加有来源依据的主支线关系。
3. **最后考虑档案库**：集中管理与检索归档故事线；恢复追踪等管理能力另行确定。

验证重点：重复消息是否减少、读者能否说清事件的新变化及发展顺序、未关注领域的重要信息是否仍有机会被看到。不能只以点击率或停留时长评价效果。

### 13.7 尚待确定

- 普通随机新闻与追踪更新的版面占比，以及重要公共信息如何获得可见性保障。
- 事件追踪的粒度：单次事件、长期议题如何区分，何时合并或拆分故事线。
- 历史回溯的时间范围、来源覆盖与成本；主支线关联的确认与纠错方式。
- 归档后的最小访问入口、保留方式与期限；是否支持恢复追踪。
- 故事线的具体交互与存储实现，以及下一版本实际纳入的范围。
